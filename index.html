Sistemas Operativos

Seguridad en Sistemas Operativos

Cinco temas para proteger un sistema, respaldar sus datos, reconocer amenazas y responder cuando algo falla.

01

Cómo dar seguridad a un sistema

La seguridad se construye por capas. Cada capa asume que la anterior puede fallar, de modo que un error en una no deja todo expuesto. Toda medida busca proteger tres propiedades.

ConfidencialidadSolo accede a la información quien está autorizado.
IntegridadLos datos no cambian sin permiso ni sin dejar registro.
DisponibilidadEl servicio responde cuando los usuarios lo necesitan.

1. Nivel aplicación

La aplicación es la puerta que usan las personas, por lo que concentra la mayoría de los ataques.

  • Autenticación. Verificar quién es el usuario con contraseña y, cuando sea posible, un segundo factor.
  • Autorización. Asignar roles y permisos para que cada usuario vea y haga solo lo que le corresponde.
  • Validación de entradas. Tratar todo dato escrito por el usuario como no confiable, para evitar inyección SQL y XSS.
  • Contraseñas con hash y sal. Guardarlas con algoritmos como bcrypt o Argon2, nunca en texto plano.
  • Comunicación cifrada. Usar HTTPS (TLS) para que los datos no viajen legibles por la red.
  • Sesiones y actualizaciones. Expirar sesiones inactivas y aplicar parches a las librerías que usa la aplicación.
  • Registros (logs). Guardar quién hizo qué y cuándo, para auditar y detectar abusos.

C#: consulta vulnerable

string sql = "SELECT * FROM Usuarios WHERE nombre = '" + txtNombre.Text + "'";
// Si el usuario escribe  ' OR '1'='1  la condición siempre es verdadera.

C#: consulta parametrizada

var cmd = new SqlCommand("SELECT * FROM Usuarios WHERE nombre = @nombre", conexion);
cmd.Parameters.AddWithValue("@nombre", txtNombre.Text);
// El valor se envía como dato, nunca como parte de la instrucción SQL.

2. Nivel base de datos

La base de datos guarda el activo más valioso. Se protege aunque la aplicación sea segura, porque alguien podría llegar a ella por otro camino.

  • Mínimo privilegio. Cada cuenta recibe solo los permisos que necesita. La aplicación no se conecta como administrador.
  • Roles. Los permisos se agrupan en roles y los usuarios se asignan a ellos, lo que facilita revisar quién puede qué.
  • Cifrado. Cifrar los datos en reposo (por ejemplo TDE en SQL Server) y las conexiones en tránsito.
  • Auditoría. Registrar accesos y cambios en las tablas sensibles.
  • Aislamiento de red. El servidor de base de datos queda detrás de un firewall, sin acceso directo desde Internet.
  • Copias de seguridad. Respaldos periódicos y probados (tema 2).

T-SQL: permisos mediante un rol

CREATE ROLE rol_consulta;
GRANT SELECT ON dbo.Productos TO rol_consulta;
ALTER ROLE rol_consulta ADD MEMBER usuario_ventas;

-- Quitar un permiso que ya no corresponde
REVOKE SELECT ON dbo.Productos FROM rol_consulta;
02

Qué es la copia de seguridad y la restauración de una base de datos

Una copia de seguridad (backup) es un duplicado de los datos guardado en otro lugar. La restauración es el proceso de recuperar la base de datos desde esa copia después de un borrado accidental, una falla de hardware, una corrupción o un ataque.

Tipos de copia

TipoQué guardaFrecuencia habitual
CompletaToda la base de datos. Es el punto de partida de cualquier restauración.Semanal o diaria
DiferencialSolo lo que cambió desde la última copia completa. Es más pequeña y rápida.Diaria
Registro de transaccionesLas transacciones desde el último respaldo del registro. Permite volver a un instante exacto. Requiere el modelo de recuperación completo.Cada 15 a 60 minutos

Regla 3-2-1

Mantener 3 copias de los datos, en 2 tipos de medio distintos, con 1 copia fuera del lugar principal. Una copia que está en el mismo servidor se pierde junto con él.

Crear las copias (SQL Server)

-- Copia completa
BACKUP DATABASE Ventas
TO DISK = 'D:\Respaldos\Ventas_completa.bak'
WITH INIT, CHECKSUM;

-- Copia diferencial
BACKUP DATABASE Ventas
TO DISK = 'D:\Respaldos\Ventas_dif.bak'
WITH DIFFERENTIAL, CHECKSUM;

-- Copia del registro de transacciones
BACKUP LOG Ventas
TO DISK = 'D:\Respaldos\Ventas_log.trn';

Restaurar en orden

Se restaura primero la copia completa, luego la última diferencial y al final los registros de transacciones. Todos los pasos menos el último usan NORECOVERY para que la base de datos siga esperando más copias.

RESTORE DATABASE Ventas
FROM DISK = 'D:\Respaldos\Ventas_completa.bak' WITH NORECOVERY;

RESTORE DATABASE Ventas
FROM DISK = 'D:\Respaldos\Ventas_dif.bak' WITH NORECOVERY;

RESTORE LOG Ventas
FROM DISK = 'D:\Respaldos\Ventas_log.trn' WITH RECOVERY;
Dos metas que fijan la estrategia. El RPO es la cantidad de datos que la organización puede perder, medida en tiempo, y define cada cuánto se respalda. El RTO es el tiempo máximo que el sistema puede estar caído, y define qué tan rápido debe ser la restauración.

Una copia que nunca se restauró no está comprobada. Conviene probar restauraciones periódicas en otro servidor y validar los archivos con RESTORE VERIFYONLY.

03

Tendencias y avances en sistemas operativos

Los sistemas operativos cambian por tres presiones: más amenazas, más equipos conectados y más cargas ejecutadas en servidores compartidos.

Virtualización y contenedores

Un hipervisor ejecuta varios sistemas operativos en una sola máquina física. Los contenedores (Docker) comparten el kernel del anfitrión, pesan menos y arrancan en segundos.

Nube y sistemas ligeros

Gran parte del cómputo corre en servidores remotos con sistemas mínimos, pensados solo para ejecutar contenedores o máquinas virtuales.

Seguridad desde el arranque

Secure Boot verifica que el cargador y el kernel estén firmados. El chip TPM guarda claves de forma protegida, y el cifrado de disco (BitLocker, LUKS) protege los datos si el equipo se pierde. Windows 11 exige TPM 2.0.

Aislamiento de aplicaciones

Android e iOS ejecutan cada app en un espacio aislado (sandbox) y piden permisos explícitos para la cámara, la ubicación o los archivos.

Sistemas inmutables

El sistema base es de solo lectura y se actualiza como una unidad. Si una actualización falla, se vuelve a la versión anterior. Lo usan ChromeOS, Android y distribuciones como Fedora Silverblue.

Rust en el kernel

Linux admite código en Rust desde la versión 6.1. El lenguaje evita por diseño muchos errores de memoria, que causan gran parte de las vulnerabilidades en C.

eBPF

Permite cargar programas verificados dentro del kernel de Linux para monitorear red y procesos sin modificar el kernel ni reiniciar.

Procesadores ARM

Apple Silicon y Windows en ARM ofrecen más rendimiento por vatio. Los sistemas operativos se adaptan a esta arquitectura además de x86.

Inteligencia artificial integrada

Asistentes dentro del sistema, como Copilot en Windows o Apple Intelligence, y gestión adaptativa de energía y recursos según el uso.

IoT y tiempo real

Dispositivos pequeños usan sistemas operativos de tiempo real como FreeRTOS o Zephyr, que garantizan tiempos de respuesta con muy poca memoria.

04

Amenazas externas

Son ataques que se originan fuera de la organización. Estos cuatro tipos aparecen con más frecuencia.

Ataques de malware

Software malicioso que se instala sin que el usuario lo sepa. Incluye virus, gusanos, troyanos, spyware y rootkits.

Cómo llega

Adjuntos de correo, programas pirata, memorias USB y vulnerabilidades sin parche.

Defensa

Antivirus o EDR, parches al día, descarga desde fuentes oficiales y uso diario sin privilegios de administrador.

Phishing e ingeniería social

Engañan a la persona, no al sistema. El phishing usa correos falsos, el smishing usa SMS y el vishing usa llamadas. En el pretexting el atacante inventa una excusa creíble.

Cómo llega

Mensajes que simulan ser de un banco, de soporte técnico o de un jefe, con urgencia y un enlace.

Defensa

Capacitación, revisar el remitente y la dirección real del enlace, autenticación multifactor y no compartir códigos.

Ataques de denegación de servicio

Saturan el ancho de banda, la CPU o las conexiones de un servidor hasta que deja de atender a usuarios legítimos. En un DDoS el tráfico viene de muchos equipos infectados que forman una botnet.

Defensa

Firewall, límite de peticiones por origen, balanceo de carga y servicios de mitigación DDoS o CDN.

Ataques de ransomware

Cifra los archivos de la víctima y exige un pago por la clave. Suele entrar por phishing o por servicios expuestos, como el escritorio remoto, sin protección.

Defensa

Copias de seguridad fuera de línea y probadas, parches, segmentación de red y mínimo privilegio. Pagar no garantiza recuperar los datos.

05

Detección y respuesta a incidentes de seguridad

Un incidente es cualquier evento que compromete la confidencialidad, la integridad o la disponibilidad de un sistema. Ninguna defensa es perfecta, así que se necesita detectar rápido y actuar con un plan.

Detección

Señales que justifican una alerta: intentos de inicio de sesión fallidos en serie, tráfico saliente inusual, procesos desconocidos, cuentas nuevas con privilegios y cambios masivos en archivos.

  • IDS / IPS. Sistemas que detectan, y en el caso del IPS bloquean, tráfico sospechoso en la red.
  • SIEM. Reúne los registros de muchos equipos en un solo lugar y genera alertas al correlacionar eventos.
  • Antivirus y EDR. Vigilan el comportamiento de procesos y archivos en cada equipo.
  • Monitoreo de integridad. Avisa cuando cambian archivos críticos del sistema.

Respuesta: ciclo de vida

El ciclo clásico de la guía NIST SP 800-61 tiene cuatro fases.

  1. PreparaciónPlan escrito, equipo responsable, contactos, herramientas y copias de seguridad listas.
  2. Detección y análisisConfirmar que es un incidente, definir su alcance y asignar prioridad.
  3. Contención, erradicación y recuperaciónAislar los equipos, eliminar la causa y restaurar desde una copia limpia.
  4. Actividad posteriorDocumentar lo ocurrido, extraer lecciones y corregir lo que falló.
Ejemplo con ransomware. Una alerta del SIEM indica cifrado masivo de archivos en un servidor. Se desconecta el servidor de la red para contener el avance, se identifica y elimina el programa malicioso, se restaura la base de datos desde la última copia verificada y se corrige la vía de entrada, por ejemplo un parche pendiente.
